# Specification: how the clinic app works and should work

Reference for agents and the owner. It holds the detail behind the decisions in `Plan.md` (D-numbers) and does not repeat the rules in `CLAUDE.md` (security rules, stack, RTL, gotchas). Read only the section you need. Where code and this file disagree, the code is what runs; fix the file. Points marked **(agent)** were decided by the agent and wait for the owner's review.

## 1. System

### 1.1 Runtime

```
Browser ─HTTPS 80/443─> Caddy ─HTTP, Docker network─> app (Node, port 3000, not published)
 Caddy: Let's Encrypt, HSTS, gzip/zstd, 35 MB body limit     app: data/clinic.db (SQLite, WAL)
                                                                  data/patients/<code>/  patient files
                                                                  data/backups/ (03:00, newest 14)
                                                                  data/trash/, data/tmp/
```

- Compose services `app` (image from `Dockerfile`, `node:24-slim`, two stages: build tools for `better-sqlite3`, then a clean runtime copy of `node_modules src views public migrations scripts`) and `caddy` (waits for `/health`). Both `restart: unless-stopped`; logs rotate 10 MB × 5. Container runs as uid 1000; Docker `HEALTHCHECK` calls `/health` (returns `ok`, no data) every 30 s.
- State lives in two places: the host data folder (`DATA_PATH`, server: `/opt/clinic-data/data`, bind-mounted to `/app/data`, outside the code so a release never touches it) and the Docker volume `clinic_caddy_data` (certificates; losing it only means a new certificate).
- `.env` variables: `DOMAIN` (resolves to the server, no scheme), `DATA_PATH` (absolute on a server; `deploy.sh` refuses relative), `TZ` (default `Asia/Tehran`; the backup runs 03:00 in it). Optional: `TRUST_PROXY` (default loopback, linklocal, uniquelocal, so `req.ip` comes from Caddy's `X-Forwarded-For`, which the per-IP lockout needs), `PORT`, `HOST`, `DATA_DIR`. No session secret: sessions are random tokens in the DB.
- Server needs: Ubuntu 24.04 (any Linux with Docker), 1 vCPU, 2 GB RAM (first image build is heaviest), 40 GB disk, public IPv4 with 22/80/443 (443/udp optional), a domain A record, outbound internet.
- Start: opens/creates `clinic.db`, applies pending migrations (tracked in `schema_migrations`), listens, starts nightly backup and the SMS timer. `SIGTERM` stops timers and closes HTTP and DB cleanly. `DOMAIN=localhost` gives Caddy a self-signed certificate (tests only).
- Deploy: `scripts/deploy.sh` (run from the release folder): backup, `docker compose up -d --build`, health wait, rollback hint, writes `current-release`. Details for people in `docs/SETUP.md`, for the server agent in `docs/DEPLOY-AGENT.md`.

### 1.2 Request life cycle (`createApp()` in `src/server.js`, in order)

1. Security headers on every response: CSP `default-src 'self'; img-src 'self' data:; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'`, `nosniff`, `Referrer-Policy: same-origin`, `Cross-Origin-Opener-Policy: same-origin`.
2. `GET /health`. 3. Static `public/` (1 h cache; CSS/JS links carry `?v=<server start>`).
4. URL-encoded body parser (200 kb, 200 parameters), default empty body.
5. `sessionMiddleware`: SHA-256 of the cookie token looked up; 8 h absolute and 30 min idle limits. Signing in again ends the old session; password reset or deactivation ends all of the user's sessions.
6. `sameOriginOnly` (every POST needs a same-site `Origin`; missing, `null`, foreign or wrong-host is refused). 7. `POST /theme` (cookie; return address must be a same-site path; open redirects blocked).
8. `/login`, `/logout`. 9. `requireUser`; the permission gate (`route-perms.js`). 10. Feature routers. 11. Persian 404 and error pages (bad URL encoding, oversized body, generic 500; logs hold no patient data).

### 1.3 Front end

Server-rendered Persian RTL EJS; plain `<form method="post">`; tabs use the CSS radio technique. Fonts Vazirmatn (text) and Geist Mono (codes), self-hosted woff2, no external request. Client JS is progressive enhancement only (password eye, Jalali picker, drop zones and image shrink, money grouping, floating labels, clock, suns, day bar, length dial, SMS template buttons, both layout editors); every page must also work without it.

### 1.4 Persian text

All text passes `src/lib/normalize.js` before save and search. SQLite function `fa_key()` (registered in `openDb()`) is compared with the normalized value, so Arabic-letter input finds Persian records. Jalali conversion lives only in `src/lib/jalali.js` (years 1200-1600). `allergies`/`conditions` are comma-separated text shown as chips.

### 1.5 Files and backups

- `patientDir()` validates `^P-\d{6}$`; `safeName()` keeps Persian letters, digits, `-_.` and blocks `..`, leading dots, separators; long Persian names are cut to fit Linux's 255-byte names. Only regular, visible files are served. A hand-copied file shows as "unclassified"; a hand-deleted file vanishes.
- Deleting a patient removes the row and moves the folder to `data/trash/<code>-<timestamp>/`. A deleted document goes to `data/trash/<code>/`. Nothing is erased; every delete is audited.
- Upload checks: extension and magic bytes (`%PDF`, `FFD8FF`, PNG signature, `DICM` at offset 128), 30 MB. Downloads: authenticated route, `Content-Disposition`, sandboxing CSP, audited.
- Nightly backup by the app: `db.backup()` at 03:00 via a `.partial` file into `data/backups/clinic-YYYY-MM-DD.db`, keep 14, plus one at start-up if today has none (`before-wipe` backups are never pruned). `node scripts/backup.js` on demand. The DB backup does not hold patient files: the real backup is copying the whole `data/` off the server.
- Full zip (flag `full_zip`, needs patients and documents view): DB snapshot, `patients.csv`, `README.txt`, per patient folder `info.csv` plus `visits.csv`, `bills.csv`/`finance/`/`storage/` CSVs when the user has those views. The DB snapshot contains everything (including password hashes), so the finance CSV gating is readability, not protection; the flag is the protection. The SMS log and `data/sms.key` are not in it.
- CSV and Excel exports guard against formula injection (`safeCell`). `.xlsx` is written by `src/lib/xlsx.js` with `archiver` (`rightToLeft="1"`).

## 2. Patients, documents, search

- **List:** search, status and sex filters, sorting, 25 per page. **Profile:** tabs personal and medical, then gallery «مدارک پزشکی» (2 tiles per row, 1 on phones; images as previews, PDF/DICOM as file tiles; open, download, delete on each). Statuses: active, pending, critical, archived. Archive and delete are separate permissions.
- **Photo, visit reason, referral** (remembered values in a `<datalist>`), optional «نام پدر» after surname (D44), SMS opt-out checkbox (`sms_optout`, with hidden `sms_optout_form=1` so CSV import never resets it; profile chip «بدون پیامک»).
- **Patient code (D13, D31, D36, D48):** `P-000123`. Next = highest in use + 1, first `P-000000`; the newest deleted code comes back, older gaps stay; when `P-999999` is in use the lowest free code is given. Row ids never reused (`patient_seq`). A code with a leftover folder is never given out (trash folders do not block). CSV import may set codes; the new-patient form may too (optional box above «هویت», only with flag `patient_code`; empty = next code and the hint names it; a posted code without the flag is ignored). Change by hand: small separate form at the bottom of the edit page (`#code`), typed twice, accepts `P-000123`, `p-123`, `123`, Persian digits (`parseCodeCell`). Refused 422: held by another patient, leftover folder, same as current, malformed, entries differ. Row update, audit row and folder rename in one transaction, rename last (a failed rename rolls back; a failed commit after rename renames back). Old code becomes free; the next automatic code stays highest + 1. Audit `patient_code`, detail `P-000005 → P-000123`; audit search by either code finds the patient. Old links 404, no redirect. Known edge: a file copied by hand into the old folder during the change lands in a folder with the old code, which then blocks that code, so it never reaches another patient.
- **Documents (D19-D21):** categories consent, lab, imaging, surgery, other; title, date, notes. Browser canvas shrinks JPG/PNG over 3 MB (long edge ≤ 2560 px, PNG becomes JPG, EXIF dropped); the server never decodes images. Both roles may delete documents.
- **New-patient documents (D49):** form is multipart; section «مدارک پزشکی (اختیاری)» with a multi-file drop box (up to 10 files, 30 MB together) and one «طبقه‌بندی مدارک» for all, only with documents edit. Any bad file or form error: no patient, no file kept, the user picks the files again. Files are saved inside the create transaction (`saveDocument`); no title/date (set later).
- **Advanced search (D22):** up to 6 rule rows, AND/OR, fixed whitelist of fields, each field offering only fitting operators; a single cycling status button is ANDed in and saved; `created_at` searchable; fields `balance`/`has_credit` (finance view) not built yet. Saved searches: own, or all for `manage_users`. A repeated or bracketed parameter (`f1[]=`) makes the search refuse (422) rather than drop the rule. Old saved searches (date "equal", `status` rule) still run. Export results as CSV/Excel.
- **Data (area `data`):** CSV import with template, preview and confirm (preview shows «کد بیمار» column; D31 notes); patients CSV/XLSX export; full zip. Import fills hidden custom boxes and skips "required".
- **Admin:** create/reset/deactivate/delete users; permissions page; paginated audit log with filters; own-password change; wipe (§9). Deleted user keeps a row (`deleted_at`, username renamed `<name>~<id>`, name still shown in the audit log).

## 3. Permissions (D25, migration 008)

- `users.perms` JSON, `users.is_owner` (at most one, partial unique index); `role` kept, unread. Levels 0 none, 1 view, 2 edit. `parsePerms` returns a clean object (unknown keys dropped, bad values 0, a flag whose area is too low is off); the owner's object is always everything. `can(user, area, level)` and `has(user, flag)` are the only checks in routes and views. `requirePerm`/`requireFlag` reply 403 in Persian. Changes apply on the next request.
- Areas: patients, documents, visits, storage, finance (none/view/edit); pdf, data, users (none/view); sms (none/view/edit).
- What each area's view/edit covers: **patients** view = list, profile, `/search` and exports, saved searches; edit = new, edit, archive, medications. **documents** view = gallery, open, download, photo; edit = upload, classify, photo change. **visits** view = `/visits`, timeline, today card, visit page, doctor's note; edit = add, edit, status, delete, note. **storage** view = items, lots, alerts; edit = stock-in. **finance** view = overview, payments, bill on visit page, history, balance strip; edit = lines, discounts, payments, refunds, moves, `/finance/pay`, patient standing discount. **pdf** = `/print/*` (also needs view on each area the document shows). **data** = `/data`, patients CSV/XLSX. **users** = `/admin/users` list.
- Flags (flag → area level): `patient_delete` (patients 2), `document_delete` (documents 2), `full_zip`, `csv_import` (data 1), `manage_users`, `audit_log` (users 1), `stock_adjust` (storage 2), `finance_settings`, `price_override` (finance 2), `patient_code` (patients 2), `layout` (patients 2), `sms_bulk`, `sms_key`.
- Presets (code, not editable): «مدیر» every area at its highest level and every flag; «کارمند» patients 2, documents 2, visits 2, storage 1, pdf 1, sms 2, flag `document_delete`. Migration 008 gave old admins «مدیر», staff «کارمند», and made the oldest active admin the owner.
- Patients view is a prerequisite for every per-patient page and every `/visits`, `/sms` path (they show patient names). Gate matching rules are in `CLAUDE.md`.
- Owner: cannot be restricted, deactivated, deleted or have the password reset by another user. `scripts/create-user.js <username> <admin|staff|owner>` (`owner` creates an admin-preset user and marks owner if none); `scripts/set-owner.js` moves ownership.
- `/admin/users/:id/permissions`: preset select + «اعمال», one card per area with radios and its flags, audited `user_perms`. New-user form has a preset select (default «کارمند»).
- Trade-off: `manage_users` can create a full «مدیر», so it is effectively full power (also reaches the wipe without finance/patients); only the owner is protected.

## 4. Visits (D23, D50, D51)

- Per-patient timeline, dashboard card «ویزیت‌های امروز» (cancelled shown on `/visits` but not on the card), `/visits`, a visit page (header, «شرح پزشک», bill, payments, print links). Both roles manage visits. Status scheduled/done/cancelled; no stored no-show («در جریان» during the span, «زمان گذشته» after). Archived patients get no new planned visits (409). Visit number = rank among the patient's non-cancelled visits by date.
- **Clash rule:** one doctor; visits on a day may not overlap (touching ends fine; cancelled frees the slot; 409 or 422 on clash). Known: visit timestamps stored without `Z` (never shown); a visit crossing midnight is not on the next day's card.
- **Durations:** 5-60 by 5, then 75, 90 (`DURATIONS`, migration 016); default 15. `overlapMessage` in `src/lib/visits.js`.
- **Day bar (D50):** `dayBookings(db, isoDate, excludeId)` returns scheduled and done visits of the day plus the tail of a visit from the day before (`start`/`end` in minutes clipped 0..1440, `time`, `until`, `name`, `status`, `fromYesterday`; cap 400). `GET /visits/day?d=<Jalali>&exclude=<id>` returns `{date, today, bookings}` JSON, `no-store`, 400 on a bad date, under the visits-view rule plus patients view. The dropdown refetches on every open and date change.
  - *Visit form:* the time box stays plain text (typing always works). Without JS a line lists the day's booked times (no names). With JS, focus/click or the clock button opens a dropdown (640 px max, viewport minus 32 px, shifted inside, flips above when no room). Ruler left to right 00:00-24:00, 120 px per hour (96 under 600 px), scrolls to the typed time, else 30 min before the first booking, else 08:00. Scheduled blocks sage, done blocks muted; the edited visit is not drawn as booked. Click on free space sets only the start, snapped to 5 min; picking stops at 23:55 (later times typed by hand); stays open until outside click or Esc. Booked block click does nothing; hover/tap shows name, span, length, «از دیروز». Pick marker = sage line with terracotta knob; a dashed block shows the chosen length and turns critical colour on a clash. Today: thin terracotta now-line. Keyboard: `role="slider"`, arrows ±5 min, PageUp/Down ±1 h, Home/End 00:00/23:55, Esc closes; polite live line. Motion: fade + 4 px rise 160 ms, marker glide 120 ms (not while dragging); off under reduced motion.
  - *`/visits` bar:* full-width card «نوار ساعت روز» for `?d=` or today: Jalali date, «امروز» chip, summary (`۳ ویزیت، ۱ ساعت و ۱۵ دقیقه رزرو` or «همه‌ی روز آزاد است»), prev/today/next links. Server-drawn HTML + SVG, no inline styles; block `<title>` shows the name; block links to the visit. Track at least 1056 px (24 hour links ≥ 44 px, out of the tab order); phones scroll sideways. Without JS each hour links to «ویزیت جدید» at that hour (edit only); with JS a free-spot click goes to exact 5-minute time. «ویزیت جدید» carries `d` and `t` through the patient search; a bad `t` is ignored. Enter on the ruler confirms; a pick past 24:00 clips and is checked only on save.
- **Length dial (D51):** select stays as no-JS fallback; with JS it is hidden but submits, and a select-styled button («۱۵ دقیقه») opens a clock face (220 px, 240 on phones). 12 values 5-60 sit where minutes sit on a clock (5 at one o'clock, 60 at twelve); sage arc from twelve to the value ending in a terracotta knob; centre shows the value; pills «۷۵» «۹۰» under «بیش از یک ساعت». Tap a value/pill, drag the knob (snaps), arrows step. Stays open until outside click/Esc. Changing the length updates the day bar's dashed block.
- Out of scope: several doctors or rooms, setting length by dragging the bar, a bar on the dashboard card.
- Code: `src/lib/visits.js`, `src/routes/visits.js`, `views/partials/day-bar.ejs`, `views/visits/{form,pick,list}.ejs`, `enhanceDayBar`/`enhancePageBar`/`enhanceDial` in `app.js`, `page-visits.css`, sprite `i-clock`. Positioning uses `element.style` (CSP allows script-set styles); the ruler is LTR so physical `left` is right there.

## 5. Storage (D26, D37, D42, D45, migration 009)

- Tables: `catalog` (kind service/item, name, `sale_price` Rial, `purchase_cost` items only and never charged, `fixed` = shown first, `low_warn`/`low_crit` overrides, `active`, hidden rows for billed deleted items), `lots` (item, `received_on`, `qty_in`, `remaining`, `expires_on`, `unit_cost`), `stock_moves` (lot, signed qty, reason in/use/return/count/waste, `line_id`, note, user, ts), `settings` (key/value).
- Settings keys: `currency` (T/R, default T), `low_warn` 10, `low_crit` 5, `clinic_name`, `clinic_address`, `clinic_phone`, SMS keys (§8). `setSettings` refuses unknown keys: add new ones to `DEFAULTS` in `src/lib/settings.js`.
- Usable lot: `remaining > 0` and (`expires_on` null or ≥ today); order `expires_on IS NULL, expires_on, id`. `takeStock(db, itemId, qty, {lineId, userId})` in a transaction sums usable remaining, throws `StockShortError(available)` if short (writes nothing), else decrements lots in order and writes one `use` move per lot. `returnStock` reverses a line's `use` moves with `return` moves on the same lots. Example: lots of 3 (sooner) and 4, using 5 takes 3+2.
- Adjustments (flag `stock_adjust`): count correction on one lot (move = difference) and waste (negative, reason `waste`, note required); writing off an expired lot is waste.
- Alerts: item warning at `low_warn`, critical at `low_crit`; lot yellow ≤ 30 days, red ≤ 10 days, «منقضی شده» when past with stock; an expired lot cannot be used.
- **Quantities (D37):** up to two decimals everywhere (`src/lib/qty.js` `parseQty`/`roundQty`). Accepted decimal signs `.` `٫` `/` and a comma before one or two digits (`0,5`); a comma before exactly three digits is thousands (`1,000`); `/` as decimal is intended (`1/2` reads 1.2, not a half). Stored as REAL in the existing INTEGER columns (`bill_lines.qty`, `lots.qty_in`, `lots.remaining`, `stock_moves.qty`, `catalog.low_*`); sums rounded with `ROUND(...,2)` in SQL and `roundQty` in JS. Shown in Persian digits with «٫» (`faDigits`); CSV keeps Latin digits and a dot. No unit name (open: ml, gram).
- **Pages:** `/storage` (items table, alert filter, «کالای جدید» needs `finance_settings`, «ورود کالا»), `/storage/items/:id` (lots, stock-in form with optional Jalali expiry/unit cost, adjustment forms, last 50 moves), dashboard «هشدارها» card (red first).
- **Undo a history row (D42):** «حذف» on «گردش کالا» (flag `stock_adjust`, `deleteMove`): count/waste reversed unless a lot would go below zero; stock-in only with an untouched lot; bill rows refused (`UNDO_MESSAGES`).
- **Delete an item (D45):** «حذف کالا» (flags `stock_adjust` and `finance_settings`): lots and history go in one transaction (`deleteItem`); bill lines keep frozen name and price; a billed item keeps a hidden catalog row (migration 014).
- Stock prints (D40, D41): see §7.

## 6. Bills, payments, finance (D27-D29, D46, migration 010)

- **Money:** whole Rial integers (`money.js`). `formatMoney(rial, cur)` gives `1,250,000 T` (Toman = Rial/10 rounded) or `12,500,000 R`, Latin digits. `parseMoney(text, cur)` accepts Persian/Arabic digits, commas, spaces, optional `T`/`R`/«تومان»/«ریال» suffix. A pasted value with a suffix is left as typed so the server reads the suffix.
- **Tables:** `visits` gains `doctor_note`, `disc_kind` (amount/percent), `disc_value`; `patients` gains the same discount pair (standing discount); `bill_lines` (visit, catalog id, kind, `name` copied, `qty`, `unit_price` frozen, `override_price`, line discount); `pay_methods`, `accounts`; `payments` (visit with no cascade, signed `amount`, kind payment/refund/move_out/move_in, `paid_on`, method, account, `move_id` pairs a move, note). Seeds: methods «نقدی» «کارت‌خوان» «کارت به کارت»; accounts «صندوق» «حساب بانکی»; a fixed service «ویزیت» priced 0.
- **Maths (`bill.js`):** line gross = (override ?? unit price) × qty, rounded half up to whole Rial (`lineGross`); line disc = amount `min(value, gross)` or percent `round(gross×value/100)`; subtotal = Σ net; bill disc same rule; owed = cancelled ? 0 : subtotal − bill disc; paid = Σ payments (all kinds); remaining = max(owed − paid, 0); credit = max(paid − owed, 0). Example: 1,000,000 R with 10% line discount and 50,000 R bill discount owes 850,000 R. The standing discount is copied into the visit's bill discount when the first line is added (only if the visit has none). Left as is: per-figure Toman rounding on the bill, standing discount copied again when the first line is re-added.
- **Behaviour:** adding an item line takes stock in the same transaction; deleting returns it; changing quantity = delete + add. Cancelling returns all item stock; back to scheduled/done takes it again (refused if short). A visit or patient with any payment row cannot be deleted (409, «ابتدا پرداخت‌ها را بازپرداخت یا منتقل کنید.»). «پرداخت کامل» records the current remaining (refused at zero). Refund: amount ≤ credit, method and account required. Move: amount ≤ credit, target visit of the same patient, not cancelled. Payment edit/delete needs finance edit; moves are deleted as a pair; edits keep sign rules and are refused if a visit's refunds and moves would exceed what it received (`assertNotOverdrawn`). Income counts on the payment day, never the visit day; a prepayment counts when paid.
- **Bill line entry (D46):** text box with `<datalist>`; the server finds the entry by `fa_key`; two entries with one name are refused with a rename hint. Override needs `price_override`.
- **Audit:** `bill_line_add line=<id> visit=<id> catalog=<id> qty=<n>`, `price_override`, `payment visit=<id> amount=<rial>`; no names.
- **Pages:** `/patients/:code/history` «سوابق درمان و مالی» (all visits, services, items, bills, payments); profile balance strip and standing-discount form.
- **Finance tab:** `/finance` overview (income today / Jalali week from Saturday / Jalali month; total remaining and credit; four server SVG charts: income per day (30 days), per Jalali month (6), revenue by source this month, pieces used per day (storage view); negative chart days draw as 0); `/finance/payments` (filters `from`, `to`, `method`, `account`, `kind`, 50 per page, totals of filtered rows); `/finance/pay` (patient search, unpaid or planned visits, payment form); `/finance/settings` (currency, letterhead, alert defaults, catalog add/edit/deactivate/delete-if-unused, methods, accounts). Charts: `src/lib/charts.js` returns SVG strings from numbers (escaped labels only), `role="img"`, `aria-label` summary, visually hidden table; no JS, CSP-safe.
- **Money boxes (D39):** `input.input-money` groups digits while typing (`enhanceMoney`): Persian/Arabic digits become Latin at once, cursor keeps its place, Backspace after a comma removes the digit beyond it. Percent boxes (≤ 3 digits) are not grouped. Without JS the server strips commas.

## 7. Print documents (D30, D38, D40, D41)

- Print-styled HTML under `/print/*` with one frame (`views/print/top.ejs`/`bottom`, `public/css/print.css`): letterhead from settings, thin sage border with corner ornaments, faint watermark, title block, tables, totals card, footer with generated time and user. A «چاپ / ذخیره PDF» link works without JS and is hidden in `@media print`. Each print is audited `print <doc>`. Chrome's print page is about 794 px wide, so scope phone-only CSS to `screen`.
- Documents: daily finance report (`/print/finance/day?d=`; pdf + finance view), day visit list (`/print/visits/day`; + visits and finance), items used (`/print/stock/usage?from=&to=&by=item|patient`; + storage), visit bill (A5; + finance), full patient record (`/print/patients/:code`; + patients, bills with finance view), full daily report, daily product report, stock on hand. Without finance, sale amounts on stock prints show «—». Page numbers on prints are not built.
- **Full daily report (D38)** `/print/visits/report?d=` «گزارش کامل روزانه» («بر اساس روز ویزیت»): needs finance, visits, patients view; A4 portrait. One block per visit by time: tinted head row (number, code, name, framed hour, reason), lines (stock-item rows highlighted warm with a «کالا» chip), line discounts as a note, a bill discount as a negative row, then one settlement row with «قابل پرداخت», the payments (method, account, amount; another-day payment shows its date in brackets) and «مانده»/«بستانکار». Ends with sums per clinic account (refunds subtracted; moved credit has no account and stays out, the footnote says so) and totals. Cancelled visits left out. Thick sage rule between patients; compact layout (smaller type, tighter rows; own A4 margins on every sheet, no frame/corners/watermark; 14 visits = 2 sheets). No CSV/Excel version.
- **Daily product report (D40)** `/print/stock/day?d=` «گزارش روزانه‌ی مصرف کالا»: needs storage, patients, visits view. Visit blocks with only stock-item lines (quantity, unit price, amount after discount), then «جمع به تفکیک کالا» (patients, total quantity, amount) and a total. Cancelled visits left out.
- **Stock on hand (D41)** `/print/stock/inventory` «موجودی انبار» (also a «چاپ موجودی انبار» button on `/storage`): today's state, one block per active item (usable count, low/critical chip) with a row per lot still holding stock (received, in, remaining, expiry with days left/past, state chip سالم / انقضا در ۳۰ روز / انقضای نزدیک / منقضی شده).
- **PDF engine (undecided, needs owner approval):** research (2026-10) recommends headless Chromium (Puppeteer `chrome-headless-shell` or Playwright `--only-shell`) printing the app's own print stylesheet, because it is the only candidate with the same shaping/bidi/`@font-face` stack as the screen. Costs: about 280 MB browser; Chrome's sandbox does not start under `cap_drop: ALL` + `no-new-privileges` without a custom seccomp profile (the documented alternatives, `SYS_ADMIN` or `seccomp=unconfined`, weaken the container); memory on 2 GB unmeasured. Before adoption run a spike: sandbox starts in the real container, rendering makes no network requests (abort all but the page's own HTML; ideally a render-only container with `--network none`), peak memory fits with concurrency 1, page timeout, kill the browser per export, explicit `/dev/shm`. Fallback: Typst (17.5 MB static binary, no browser; open RTL issues and a panic on Arabic combining marks in 0.14/0.15 — pin and test with diacritics). Rejected: pdfkit, pdfmake, jsPDF (no working RTL shaping). Keep Latin digits in `dir="ltr"` spans for `1,250,000 T`.

## 8. SMS (D32-D35, migration 011)

- **Provider:** IranPayamak; each clinic uses its **own** account and types its API key in «پیامک → تنظیمات». The developer's key is never used. Feature is dormant until a key is saved and SMS is switched on.
- **Reminders:** automatic by a 60 s server timer (`scheduleSms` in `server.js`, overlap-guarded, `unref()`ed, stopped on shutdown; after a send, or at most every 30 min, the engine reads the balance). Lead per visit (visit form field «یادآوری»; empty = clinic default): `now`, `h2` two hours before, `d1` one day before at the send hour (default 17:00), `d2`, `none`. Window 08:00-21:00 (`TZ=Asia/Tehran`): "hours before" earlier than 08:00 moves to 21:00 the evening before; later than 21:00 moves to 21:00 the same day; a due message sent late waits for 08:00. A visit already started gets nothing («زمان ارسال گذشته است»). Max 2 per visit; a moved visit follows the new time (after sending: one new reminder); cancelled/done send nothing; one message per visit. Skipped with a visible reason (log and visit card): opted out, archived, no valid mobile (`phone` normalized to `09XXXXXXXXX` by `normalizeMobile`), cap reached. Switching SMS on queues reminders for existing planned visits only after the clerk ticks a confirmation of the count shown (server recompares). Body is built at send time from the visit and template, then stored. Content: name, date, time only; never medical. Wording: filled from data with draggable buttons «نام» «تاریخ» «ساعت» (`{نام}` etc.), max 300 characters, plain free text. `DEFAULT_TEMPLATE` in `src/lib/sms-rules.js` is provisional (owner defers wording, digit style, date format; date text like «پنجشنبه ۳۰ام مهرماه»).
- **No double sends:** one reminder row per `(visit_id, stamp)` (unique index). A tick claims a row with `UPDATE ... SET status='sending' WHERE status='pending'` and checks `changes`. A row stuck in `sending` after a crash becomes `failed` «نتیجه نامشخص» at start-up (`recoverStuck` only then) and is never resent automatically (staff may press «ارسال دوباره»). Timeouts and 5xx are "unknown" and not retried; only a connection error proving the request never left (`ENOTFOUND`, `ECONNREFUSED`, `EAI_AGAIN`, `ENETUNREACH`) is retried, 5 min apart, 3 tries; a retried row keeps its 5-minute wait (planner resets `due_at`).
- **Credentials:** `sms_credentials` row (id 1) holds the key as AES-256-GCM; the encryption key is a random 32-byte file `data/sms.key` (mode 600, created with `wx`) outside the DB, backups and zip, so a stolen backup cannot send; restoring onto a new server means typing the key again. UI shows only the last 4 characters; the key field is `type=password autocomplete=off` and never put back in a page. A new key is checked with the balance call first. A wrong/damaged `sms.key` makes the key unreadable («کلید ثبت نشده») and never crashes start-up. The key matches `/^[A-Za-z0-9_.-]{20,200}$/`; never in a view, log, error, audit, DB plaintext, backup or zip.
- **Provider client** `src/lib/sms-provider.js`: Node `fetch`, fixed base `https://api.iranpayamak.com/ws/v1/`, `Api-Key` header, `redirect: 'error'`, 15 s timeout, UTF-8 JSON. Calls `GET account/balance`, `POST sms/simple` (`text`, `line_number`, `recipients`, `number_format`). **Every send carries `number_format: 'persian'`**: the provider answers 422 without it though its docs call it optional. `data.status` `insufficient-balance` becomes failed «اعتبار کافی نیست»; `pending-approval`, `in-queue`, `sent` count as accepted (a `pending-approval` message is still delivered). Errors from the provider are shown shortened, never with headers. Tests inject `createApp({ smsFetch })`; never the network; never test Persian with Git Bash `curl`.
- **Data (011):** `patients.sms_optout`, `visits.reminder_lead` (NULL = default), `sms_credentials`, `sms_messages` (kind reminder/custom/bulk/alert/test; status pending/sending/sent/failed/skipped/cancelled; `reason`, `due_at` epoch ms, `attempts`, `provider_id`), settings `sms_enabled sms_line sms_lead sms_hour sms_template sms_alert_phone sms_low_threshold sms_low_alerted sms_balance sms_balance_at`. Rows older than 180 days are purged daily; rows of a deleted patient/visit cascade. The log is not in the full zip.
- **Low credit:** when balance falls to the threshold (messages left, default 10) one SMS goes to the alert number, once per drop, again only after recovering above; the dashboard card also warns (an alert SMS cannot be sent at zero credit).
- **Custom and bulk:** custom message from a patient profile (max 500, live parts count, shows the number, disabled with the reason when opted out/no mobile). Bulk (flag `sms_bulk`): recipients from one of the user's saved searches (users with `manage_users` see all); skips opted-out, archived, invalid numbers and counts them; same number twice goes once; cap 500 («حداکثر ۵۰۰ گیرنده در هر ارسال»); step 1 pick search + text (`{نام}` only), step 2 preview (eligible, skipped, SMS parts per message and total, balance, a box where the count must be typed again; a changed count re-shows the preview), step 3 queues `kind='bulk'`. Custom and bulk rows are not held by the window; reminders are.
- **Routes (all also need patients view; first match wins):** `POST /sms/key`, `POST /sms/test` (flag `sms_key`), `GET,POST /sms/bulk` + `POST /sms/bulk/confirm` (flag `sms_bulk`), `POST /sms/settings` and `POST /sms/:id/retry` (sms edit), `GET /sms`, `GET /sms/settings` (sms view), `GET,POST /patients/:code/sms` (sms edit).
- **Screens:** one sidebar button «پیامک» (`i-mail`) with sub-nav «گزارش ارسال» · «ارسال گروهی» (only with `sms_bulk`) · «تنظیمات». Log: newest first, 50 per page, filters status/kind; chips در انتظار / ارسال شد / ناموفق (with «ارسال دوباره») / ارسال نشد (reason) / لغو شد; top strip shows balance and read time or «پیامک غیرفعال است»/«کلید ثبت نشده». Settings: switch (with the count confirmation), sender line (default `90008361`, `/^[A-Za-z0-9]{3,20}$/`), default lead and send hour (8-21), wording editor (live characters/parts `smsParts`, sample line), and with `sms_key`: key box, alert number, threshold (1-1000), «پیامک آزمایشی». Visit card chip from the latest reminder row (sent / waiting with due time / failed with reason / not sent with reason; none for lead `none`). Dashboard «پیامک» card only when something needs attention (no key, low balance, failures in the last 24 h).
- **Audit:** `sms_settings` (no values), `sms_key_set`, `sms_key_remove`, `sms_test`, `sms_send` (`1 recipient`), `sms_bulk` (`N recipients`), `sms_retry`. Timer sends write no audit row (the log is the record). Never a key, number or text in `detail`.
- **Safety:** failure never blocks saving a visit or any page (engine catches everything and logs a short code); outbound calls only to the fixed URL; text is EJS-escaped.
- **Not built:** delivery-status polling, inbox polling and «لغو۱۱» replies (shared lines cannot receive replies; an operator-side «لغو۱۱» block shows as provider failures), other triggers (birthday, balance, closure), SMS cost in finance. Opt-out is a checkbox only. Left as is: a failing balance call retried every tick; a 40×{نام} template cut before {تاریخ}.
- **Provider facts (verified live 2026-10-24, personal panel, نقره‌ای plan):** economy plan has no API; the docs site is branded FarazSMS (operator Zarin Ertebatat Asia) and is incomplete, so trust live behaviour. `GET account/profile`; `GET account/balance` (`balance_amount` toman, `balance_count` messages); `GET lines/accessible` (shared lines, 248 toman each; `90008361` is the web-service line); `POST sms/simple` (200, `data.id`); `GET send_request/{id}`; plain Persian text delivers as UTF-8 JSON. Terms rule 2 (medical field, Medical Council letter): support said on 2026-10-24 the letter is not needed for a clinic's own visit reminders. Client setup: نقره‌ای plan or higher, verify identity in the panel, key from panel → وب‌سرویس → لیست کلیدهای دسترسی, paste in the app, press «پیامک آزمایشی»; shared lines may land in spam; a dedicated line needs business documents and about 72 working hours.

### 10.2 Custom boxes (D53)

| Type | Input | Stored | Size |
|---|---|---|---|
| `short_text` «متن کوتاه» | text ≤ 200 | normalized text | half |
| `long_text` «متن بلند» | textarea ≤ 5000 | normalized text | full |
| `number` «عدد» | `inputmode=decimal`, ≤ 2 decimals, leading minus, `.` or `٫` (`,` refused) | ASCII decimal | half |
| `date` «تاریخ» | Jalali text box | ISO | half |

| `yes_no` «بله / خیر» | two radios + none | `1`/`0` | half |

- Name 1-60 characters, unique among live custom boxes, built-in box names, every CSV import header and English field name (`isReservedHeader`/`reservedHeaderKeys` in `csv.js`), compared after `faKey`. Choices keep an id for life (`choices` JSON `[{"id":1,"label":"خشک","hidden":false}]`; `custom_boxes.choice_seq`, migration 018, holds the highest id ever given so ids are never reused); choices can be appended later; an unused choice can be removed, a used one only hidden (still shown on profile and exports) **(agent)**. Removing a box from the layout hides it; deleting for good only while no patient has a value (confirm-delete partial; row gets `deleted_at`, id never reused). Values validated on the server by one function shared by the form and CSV import (`checkCustomValue`). An empty box has no `patient_values` row; saving a patient writes values in the same transaction.
- **Search:** every live custom box (shown or hidden) is a field `c<id>`; the server accepts the key only for a live id read from the table; fixed SQL per type: `EXISTS (SELECT 1 FROM patient_values pv WHERE pv.patient_id = patients.id AND pv.box_id = ? AND <operator on pv.value>)` with id and value bound. Text: `contains`, `not_contains`, `equals` via `fa_key`; number: `eq`, `lt`, `gt`, `between` on `CAST(pv.value AS REAL)`; date: `before`, `after`, `between`; choice: `is`, `is_not`; yes/no: `is`. "Not contains"/"is not" also match patients with no value.
- **CSV/Excel/`patients.csv`/`info.csv`:** custom columns after built-ins, in layout order then hidden ones by creation order; header = box name; cells as people read them (text, number with `.`, Jalali `1403/05/12`, choice label, «بله»/«خیر»), `safeCell`; one shared function builds all four. **Import:** header matches a live custom box by name after `faKey`; a choice label must match exactly after normalization; yes/no takes «بله»/«خیر»/`1`/`0`/`yes`/`no`; a bad cell fails its line in Persian; hidden boxes are filled; the template lists the custom boxes shown on the form.
